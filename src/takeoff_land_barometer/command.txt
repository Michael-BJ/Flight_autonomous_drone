------------------------------------------------------------------------
WHAT IS DIFFERENT FROM takeoff_land (everything else is identical)
------------------------------------------------------------------------

  The node is takeoff_land's TakeoffLandNode + a barometric altitude layer
  (takeoff_land_barometer/baro_altitude.py). Every setpoint z is sent as

      z_sp = z_ekf + baro_gain * (alt_target - alt_baro)

  so PX4 sees the BAROMETRIC altitude error, not the GPS-height error.
  Slow GPS-height drift and GPS z jumps no longer move the drone.
  Below baro_ground_effect_alt (1.0 m) the barometer is not used
  (propeller downwash): the first/last metre dead-reckon on the EKF z
  like takeoff_land does.

  PRE-FLIGHT ground reference (replaces the EKF-only check):
    barometer (filtered): rate >= 5 Hz, std < 0.08 m, spread <= 0.30 m
    EKF z:                std < ekf_gate_std (0.15 m), spread <= 0.5 m
                          (|z| check effectively OFF: max_ground_z 1000)
  Terminal shows  balt=<barometric alt>(BARO|EKF-LOCK|STALE)  ekf_alt=...

  ABORTS added: barometer stream lost > baro_stale_abort_s (5 s) -> AUTO.LAND.
  max_alt_error is measured on the barometric altitude.

------------------------------------------------------------------------
PARAMETERS (new; the rest are takeoff_land's — see takeoff_land/command.txt)
------------------------------------------------------------------------

  baro_gain               0.7   loop gain (1.0 = PX4's own MPC_Z_P response)
  baro_tau_s              1.0   low-pass on the raw barometer (0.085 m RMS noise
                                at 10 Hz measured 2026-09-13 -> ~3 cm)
  baro_ground_effect_alt  1.0   below this: EKF dead-reckoning, no barometer
  baro_blend_s            2.0   blend when switching to the barometer
  baro_glitch_m           1.5   single-sample outlier rejection
  baro_stale_s            1.0   no sample -> EKF fallback
  baro_stale_abort_s      5.0   no sample -> abort (0 = never)
  baro_max_cmd_offset     1.5   |z_sp - z_ekf| bound
  baro_gate_std           0.08  pre-flight, filtered barometer std
  baro_gate_drift         0.30  pre-flight, filtered barometer peak-to-peak
  baro_min_rate_hz        5.0   pre-flight, /mavros/altitude rate
  ekf_gate_std            0.15  pre-flight, EKF z std (takeoff_land: 0.08)
  max_ground_z            1000  (takeoff_land: 1.0)
  max_ground_drift        0.5   (takeoff_land: 0.2)

------------------------------------------------------------------------
FIRST TEST (propellers OFF, then a low hover)
------------------------------------------------------------------------

  1. Pixhawk powered >= 3 min before the ground reference (barometer warm-up).
  2. Propellers OFF: launch, read "Ground reference OK. baro h_ground=... |
     EKF ground_z=... | offset ekf-baro=..." and the balt= line (should sit
     near 0.00 m EKF-LOCK). Kill-switch test as documented for takeoff_land.
  3. target_alt:=1.5 hover: watch balt= (barometric) against what you see,
     and ekf_alt= drifting away from it — that drift is what used to move
     the drone.

------------------------------------------------------------------------
OPTIONAL: PX4 ALSO USES THE BAROMETER (EKF2_HGT_REF 0 + EKF2_GPS_CTRL 5)
------------------------------------------------------------------------

  NOTE (2026-10-19): PX4 now uses the H-Flow range finder as its height
  reference (EKF2_HGT_REF 2, barometer fallback). See ~/drone_ws/HISTORY.md.
  This section describes the earlier barometer setup.

  This package works WITHOUT changing PX4 parameters. But PX4 itself still
  keeps GPS height in its EKF (EKF2_HGT_REF 1, EKF2_GPS_CTRL 7), so fast GPS
  jitter still enters through the EKF vertical velocity, and the pre-flight
  gate still refuses when EKF z shakes quickly.

  Stronger: move the EKF height reference to the barometer and turn GPS
  height off. Tested 2026-09-13 13:07 and 13:15 (90 s static: EKF z 0.42 m
  p2p vs GPS 1.7-2.7 m). Reverted to GPS at 13:4x at the owner's request.
  The barometer package stays compatible: EKF z is then ~ barometer, offset
  ~ constant.

    EKF2_HGT_REF   1 (GPS)  -> 0 (Baro)   EKF height reference
    EKF2_GPS_CTRL  7        -> 5          bit1 (GPS height) OFF; horizontal
                                          position (bit0) + 3D velocity
                                          (bit2) stay ON.  BOTH are REQUIRED:
                                          HGT_REF 0 alone is not enough (13:00,
                                          z still followed GPS, corr +0.99).

  Requirements: drone DISARMED, propellers off, MAVROS connected
  (ros2 launch takeoff_land mavros_only.launch.py). This writes to the
  Pixhawk flash and applies to ALL flight modes, including the pilot's
  Position mode.

  Option 1 - through MAVROS (second terminal, after sourcing):
    ros2 service call /mavros/param/pull mavros_msgs/srv/ParamPull "{force_pull: true}"
    ros2 param set /mavros/param EKF2_HGT_REF 0
    ros2 param set /mavros/param EKF2_GPS_CTRL 5
    # read back from the flight controller to confirm:
    ros2 service call /mavros/param/pull mavros_msgs/srv/ParamPull "{force_pull: true}"
    ros2 param get /mavros/param EKF2_HGT_REF      # must be 0
    ros2 param get /mavros/param EKF2_GPS_CTRL     # must be 5
  Option 2 - QGroundControl > Vehicle Setup > Parameters, search for
    EKF2_HGT_REF and EKF2_GPS_CTRL, change them, then Tools > Reboot Vehicle.

  After writing: UNPLUG BATTERY + USB, power the Pixhawk again (clean EKF
  init), wait >= 3 minutes (barometer warm-up: -3.5 m in the first 2
  minutes), then run this package. Note: EKF z on the ground will not be 0
  (13:15: -3.4 m); that is normal for this package (max_ground_z is 1000).
  Record the before/after parameters in ~/drone_ws/HISTORY.md and the
  knowledge base.

  Effect on the program: nothing needs to change. balt= and ekf_alt= will be
  almost equal; the ekf-baro offset almost constant.
  Risk notes: the barometer drifts with the weather and with wind / direct
  sun (cover the Pixhawk with foam), and ground effect (EKF2_GND_EFF_DZ 4.0,
  EKF2_GND_MAX_HGT 0.5 already handle <= 0.5 m).

  BACK TO GPS (after the GPS is replaced, or when in doubt):
    ros2 param set /mavros/param EKF2_HGT_REF 1
    ros2 param set /mavros/param EKF2_GPS_CTRL 7
    ros2 service call /mavros/param/pull mavros_msgs/srv/ParamPull "{force_pull: true}"
    ros2 param get /mavros/param EKF2_HGT_REF      # must be 1
    ros2 param get /mavros/param EKF2_GPS_CTRL     # must be 7
    then unplug battery + USB and power the Pixhawk again.
  DO NOT use write_px4_params:=true in fm_deploy* (the simulation parent
  class writes EKF2_HGT_REF 1 back).
